### 2. 已实现的核心计时修复

#### 2.1 后台恢复后补记全部完整番茄

原逻辑只保存 `min(未记录时长, 一个番茄时长)`，随后把已记录位置推进到全部累计时长。60 分钟一个番茄、恢复到 120 分钟时，第二个 60 分钟因此被跳过。

新增 `js/local-timer-core.js`，根据实际经过时间计算应记录的完整区间，并保留未满番茄的尾数。记录使用各区间真实结束时间，避免集中记在恢复页面的时刻。

| 情况 | 已实现的结果 |
|---|---|
| 60 分钟一个番茄，恢复到 120 分钟并确认全部计入 | 两个完整番茄，共 120 分钟 |
| 恢复到 145 分钟并确认全部计入 | 记录两个完整番茄，保留约 25 分钟尾数 |
| 已记录 60 分钟，随后恢复到累计 180 分钟 | 仅补记尚未记录的两个番茄 |
| 再次刷新或重复执行恢复 | 从数据库最新进度继续，不重复生成已提交记录 |

记录带有会话 ID、顺序号及逻辑分段 ID。跨暂停或等待确认的区间不会被错误拼成连续专注时间；必要时一个逻辑番茄可对应多条实际时间片段。

#### 2.2 持久化计时会话

数据库名称仍为 `PomodoroDB6`，结构版本从 2 升级为 3，保留原有八张业务表，新增：

- `TimerSession`：保存当前计时会话、模式、任务归属、时长设置、已记录进度、未记录区间、最近执行时间及待确认区间。
- `LocalMeta`：保存数据维护标记和导入恢复日志。

计时器由明确的主程序入口接入新的适配器 `js/local-timer-ui.js`，不依靠遍历 React 内部 Fiber 来寻找计时器。

运行期间约每 30 秒保存一次状态，番茄边界及开始、暂停、继续、停止等操作也触发保存。界面每秒更新不意味着每秒写数据库。

#### 2.3 长时间中断后的确认

按照用户选择，长时间中断先询问是否计入，再保存记录。当时检测阈值为 5 分钟，位于 `local-timer-core.js` 的 `GAP_MS` 常量。

恢复框提供：

1. 全部计入。
2. 按指定专注截止时间计入。
3. 不计入中断部分。
4. 是否在确认后继续计时。

等待确认期间不累计新增专注时间。待确认区间写入数据库，再次刷新不会扩大或重复处理该区间。系统时间明显回退也会进入确认流程。

中断起点取最近持久化的计时位置，并不代表能够精确识别浏览器冻结或电脑休眠发生的时刻。用户可以调整截止时间。

#### 2.4 事务提交与防重复

新增 `js/local-data.js`，在同一个 IndexedDB 事务中提交番茄记录与会话进度，以事务 `oncomplete` 作为成功依据。

- 写入中途失败：记录与进度一起回滚。
- 写入成功、界面尚未刷新就重载：以数据库状态恢复，避免重复补记。
- 同一页面中的操作按队列执行。
- 多标签页写入使用短时 Web Lock 协调，并在事务中重新读取当前会话。
- 不通过延时防抖来假定“应该已经保存成功”。

#### 2.5 暂停、切换任务及倒计时

暂停会结算当前连续运行段，暂停期间不记为专注。继续后使用新的真实时间区间。

切换任务前结算旧任务，随后采用新任务的番茄时长，避免继续沿用旧任务的计时起点和时长。

正向计时持续累计；倒计时按照自动工作、自动休息、禁用休息及长休息设置推进状态。未启用自动开始时，到等待状态后不继续把等待算作专注。

行为变化：停止时保留不足一分钟的有效片段，不再沿用原先直接丢弃短片段的阈值。暂停、停止或不连续的恢复区间可能产生部分番茄记录，因此“记录条数”不应直接理解为“完整番茄数量”。

### 3. 已实现的数据安全修复

#### 3.1 完整备份与导入校验

原导入前自动备份仅包含 localStorage，无法恢复任务和专注记录。现在导出及导入前备份包含原业务表、计时会话和本地设置。

导入前检查应用标识、备份版本、必需数据表、记录 ID、重复 ID、专注时长、设置类型以及计时会话格式。旧版完整备份仍受支持；只有设置的旧式自动备份会被拒绝，避免覆盖完整数据库。

浏览器下载动作已实现，但程序不能保证用户最终把下载文件保存到了期望位置，提示会要求检查下载结果。

#### 3.2 原子导入及跨存储恢复

所有业务表在同一数据库事务中替换，写入错误会报告失败，不再被转换成成功。

IndexedDB 与 localStorage 无法使用一个原生事务同时提交。因此采用数据库中的持久化导入日志保存目标设置和原始完整快照：

- 数据库写入成功后应用设置。
- 设置写入失败时恢复原数据库和原设置。
- 导入途中页面关闭后，下次启动检查日志，继续完成或回滚。
- 维护期间设置数据库标记，旧业务管理器的写事务也检查该标记，减少与导入、重置互相覆盖的风险。

#### 3.3 备份中的未结束计时

新版备份保留未记录完的专注区间。导入正在运行的会话时，将其变为待确认状态，并把可确认区间限制在备份生成时刻，不把备份生成后到今天的时间算作专注。

从备份恢复的确认框默认不勾选继续计时。旧版备份没有计时会话表时，不创建运行中的会话。

#### 3.4 启动误删与重置竞态

移除了“localStorage 的 `Version` 缺失或为零就删除 `PomodoroDB6`”的启动路径。

重置操作现在等待数据库与设置处理完成后再返回成功，并生成完整备份。修复了数据库仍在清除、应用却已经刷新或提示成功的竞态。

### 4. 其他已实现修改

#### 4.1 主题保存失败

主题写入失败会向上传递错误并显示提示，失败的主题不会被当成保存成功后激活。

增加主题 JSON 总量限制，允许已有超限数据通过删除逐步缩小。图片压缩失败时不再回退保存未经压缩的大图。

本阶段采用 localStorage 保存主题图片，修复集中在错误传播、限制体积和避免失败后激活。

#### 4.2 外部请求边界

- 使用解析后的精确主机名判断 Bing 白名单，避免域名子串匹配绕过。
- fetch 对字符串、URL 与 Request 输入统一处理。
- 为页面增加 CSP，限制连接、图片、字体、媒体等来源。
- 停用旧主同步入口，移除已定位的图片形式遥测发送点。
- 保留 Bing 壁纸的明确允许来源，因此不能把此版本描述为“完全没有任何外部资源功能”。

#### 4.3 音频与冗余补丁

浏览器测试发现原静音音频解码产生未处理异常。音频接入改为有错误处理的 HTMLAudio 播放，静音模式不再加载循环静音音频。

去掉评分弹窗补丁中的 React 内部树遍历与高频重复设置，改用现有偏好开关。

#### 4.4 本地启动

增加 `scripts/server.cjs`，仅绑定 `127.0.0.1`，禁用缓存，避免依赖 npm/http-server；`start.ps1` 先切换到项目目录，然后优先使用这个服务器。

该变更源于验收环境中全局 npm 命令失效。测试直接使用 node 执行，没有修复或更改用户的全局 npm 安装。

浏览器集成测试使用测试文件内的临时 HTTP 服务器；生产服务和音频 Range 已在第二阶段完成独立验收。

### 2. 新问题的原因与具体修复

#### 2.1 停止后持久化会话没有真正归零

第一阶段 `local-timer-core.js` 的 `stop` 分支只将状态改为 `initial`、清空 `phaseElapsed`，保留了 `totalSeconds` 和 `recordedSeconds`。正计时 `view()` 仍读取累计时长。

所以停止时界面暂时显示零，后续 `flush`、任务完成、取消或重载再次从会话生成界面，就把已记录时长显示回来。

现在 `reduce()` 的 `stop` 和 `mode` 分支先保存有效专注，再清空累计显示、已记录进度及剩余片段，重置时间锚点。`view()` 对 `initial` 明确返回零，兼容之前已经保存的停止状态。

**归零不会删除 `Pomodoro` 表中的历史记录。** 会话记录顺序号和逻辑分段号保留，防止后续复用旧记录 ID。新一轮开始使用新会话。

#### 2.2 空 ID 没有清除旧界面选择

旧 Redux 的 `DELETE_TIMING_TASK` 只有传入 ID 与当前任务/子任务 ID 匹配时才清除选择。第一阶段取消关联后传入空字符串，无法匹配已有任务，导致会话和界面不同步。

现在 `local-timer-ui.js` 的 `updateTimingTask()` 遇到空任务调用明确的 `clearTask()` 回调，在 `js/main.js` 接入中通过 `initTimingTask(null, null)` 同时清除任务和子任务。两个偏好计时 ID 也与会话同步。

`detach` 先保存有效专注，再解除任务、停止并归零。叉号只解除计时关联，任务仍在列表中，不删除、不标记为完成。

圆圈完成任务的路径先冻结并保存计时，再执行原有任务/子任务完成逻辑，最后解除关联，防止旧回调再次累计。完成子任务不会自动完成父任务。

#### 2.3 旧订阅捕获了修改前的函数

旧组件构造时先 `events.on(..., timer.startForTask)`，随后才覆盖同名方法。事件总线保留旧函数对象，部分入口因此绕过新逻辑。

现在明确提供十个计时订阅的事件、名称与原函数，移除旧订阅，改为动态调用当前 `timer[name]`。通过事件总线启动任务也使用新适配器。

闲置时长更新改为持久化的 `configure` 操作，正在进行的工作保留本段时长设置；卸载后的旧延迟刷新直接退出。

#### 2.4 当前操作规则

| 操作 | 当前行为 |
|---|---|
| 暂停 | 保存有效片段，保持累计显示，可继续 |
| 停止 | 保存有效片段，当前计时归零，保留任务选择 |
| 停止后点叉号 | 清除任务/子任务选择，保持零，任务仍未完成 |
| 停止后点圆圈 | 完成所选任务或子任务，清除选择，保持零 |
| 运行中点叉号 | 保存、停止、归零并解除关联，任务保留 |
| 运行中点圆圈 | 先冻结保存，再完成任务，解除关联并归零 |
| 重新开始 | 新会话开始，不带入旧累计显示 |

### 3. 接入路径修复

#### 3.1 普通完成通知

核心增加 `events` 返回值，分别表达工作/休息结束。不能用“生成了一条记录”推断完成，因为暂停、停止和不连续专注也产生部分记录。

适配器只在本次事务跨过正常计时边界时提示：正计时完整番茄发通知；倒计时工作结束发通知和工作铃声；休息结束发通知和休息铃声。历史恢复确认只显示补记结果，不连续播放旧提醒；单纯部分记录不触发完成提示。

本地浏览器在 `Notification.permission` 已为 `granted` 时使用标准通知，否则保留原环境入口。本轮没有自动申请权限，也没有新增授权设置页面。

测试替换通知与铃声调用，验证次数、顺序及去重。

#### 3.2 React 卸载清理

`componentWillUnmount()` 调用 `dispose()`，清除新轮询、旧间隔、十个计时业务订阅、恢复弹窗、页面及跨页监听和仍由本组件持有的 `webBridge` 回调。清除桥接入口前检查函数归属，避免删除新组件接管的函数。

异步挂载和排队操作检查已卸载状态，避免加载结束后重新开启轮询。原组件仍是压缩 bundle 中的类组件，没有完成源码拆分。

#### 3.3 跨标签页任务及报表刷新通路

计时事务成功后，`local-data.js` 的 BroadcastChannel 消息携带新提交记录。其他页面读取最新会话，将记录送入原 `POMODORO_NEW`、任务和清单刷新通路。

按记录所属任务 ID 获取并刷新任务，避免切换任务后只刷新新任务。已验证另一页收到记录事件、当前任务番茄进度与会话更新。

无 Web Locks 的隔离环境也验证了双页同时确认时，IndexedDB 事务不会重复生成记录。

#### 3.4 白噪音恢复与播放归属

即使保存状态已为 `work`，恢复时也重新同步背景音。音频适配处理页面隐藏、pagehide/pageshow、焦点和用户点击；暂停/休息停止白噪音，返回或用户操作后重试。试听结束或报错恢复背景音。

支持 Web Locks 时用独立的 `focustodo-local-background-audio` 锁保证一个标签页播放。它与数据库短时写锁分开，不阻塞保存。

模拟 Audio 验收了短时重载、隐藏恢复、暂停和双标签页播放归属。

#### 3.5 本地服务器和启动脚本

独立验收 `scripts/server.cjs`，补齐 `bytes=-N` 音频尾部范围。支持单段闭区间、开放尾部及后缀范围；非法范围返回 416，多段范围不支持。

继续仅监听 `127.0.0.1`，禁用缓存，拒绝隐藏路径与 scripts/tests/node_modules。端口被占用时报告失败并退出。

`start.ps1` 增加 `-NoBrowser` 和 `-Port`，保证访问地址与 Node/Python 端口一致。默认仍为 5500；Node 分支临时设置 FOCUS_PORT，结束后恢复原值。

通过实际执行 PowerShell 脚本并替换服务器命令，验证目录与端口传递，测试阻断自动打开浏览器；另在独立浏览器加载生产服务器，验证应用启动和 M4A 范围返回。

双击 bat、自动打开浏览器和 Python 回退没有完整端到端验收。更换主机名/端口会使用不同浏览器存储，日常应保持原访问地址。
