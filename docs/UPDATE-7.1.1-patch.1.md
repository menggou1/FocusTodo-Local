## 2. 已实现的核心计时修复

### 2.1 后台恢复后补记全部完整番茄

原逻辑只保存 `min(未记录时长, 一个番茄时长)`，随后把已记录位置推进到全部累计时长。60 分钟一个番茄、恢复到 120 分钟时，第二个 60 分钟因此被跳过。

新增 `js/local-timer-core.js`，根据实际经过时间计算应记录的完整区间，并保留未满番茄的尾数。记录使用各区间真实结束时间，避免集中记在恢复页面的时刻。

| 情况 | 已实现的结果 |
|---|---|
| 60 分钟一个番茄，恢复到 120 分钟并确认全部计入 | 两个完整番茄，共 120 分钟 |
| 恢复到 145 分钟并确认全部计入 | 记录两个完整番茄，保留约 25 分钟尾数 |
| 已记录 60 分钟，随后恢复到累计 180 分钟 | 仅补记尚未记录的两个番茄 |
| 再次刷新或重复执行恢复 | 从数据库最新进度继续，不重复生成已提交记录 |

记录带有会话 ID、顺序号及逻辑分段 ID。跨暂停或等待确认的区间不会被错误拼成连续专注时间；必要时一个逻辑番茄可对应多条实际时间片段。

### 2.2 持久化计时会话

数据库名称仍为 `PomodoroDB6`，结构版本从 2 升级为 3，保留原有八张业务表，新增：

- `TimerSession`：保存当前计时会话、模式、任务归属、时长设置、已记录进度、未记录区间、最近执行时间及待确认区间。
- `LocalMeta`：保存数据维护标记和导入恢复日志。

计时器由明确的主程序入口接入新的适配器 `js/local-timer-ui.js`，不依靠遍历 React 内部 Fiber 来寻找计时器。

运行期间约每 30 秒保存一次状态，番茄边界及开始、暂停、继续、停止等操作也触发保存。界面每秒更新不意味着每秒写数据库。

### 2.3 长时间中断后的确认

按照用户选择，长时间中断先询问是否计入，再保存记录。当前检测阈值为 5 分钟，位于 `local-timer-core.js` 的 `GAP_MS` 常量；尚未提供设置界面。

恢复框提供：

1. 全部计入。
2. 按指定专注截止时间计入。
3. 不计入中断部分。
4. 是否在确认后继续计时。

等待确认期间不累计新增专注时间。待确认区间写入数据库，再次刷新不会扩大或重复处理该区间。系统时间明显回退也会进入确认流程。

中断起点取最近持久化的计时位置，并不代表能够精确识别浏览器冻结或电脑休眠发生的时刻。用户可以调整截止时间。

### 2.4 事务提交与防重复

新增 `js/local-data.js`，在同一个 IndexedDB 事务中提交番茄记录与会话进度，以事务 `oncomplete` 作为成功依据。

- 写入中途失败：记录与进度一起回滚。
- 写入成功、界面尚未刷新就重载：以数据库状态恢复，避免重复补记。
- 同一页面中的操作按队列执行。
- 多标签页写入使用短时 Web Lock 协调，并在事务中重新读取当前会话。
- 不通过延时防抖来假定“应该已经保存成功”。

### 2.5 暂停、切换任务及倒计时

暂停会结算当前连续运行段，暂停期间不记为专注。继续后使用新的真实时间区间。

切换任务前结算旧任务，随后采用新任务的番茄时长，避免继续沿用旧任务的计时起点和时长。

正向计时持续累计；倒计时按照自动工作、自动休息、禁用休息及长休息设置推进状态。未启用自动开始时，到等待状态后不继续把等待算作专注。

行为变化：停止时保留不足一分钟的有效片段，不再沿用原先直接丢弃短片段的阈值。暂停、停止或不连续的恢复区间可能产生部分番茄记录，因此“记录条数”不应直接理解为“完整番茄数量”。

## 3. 已实现的数据安全修复

### 3.1 完整备份与导入校验

原导入前自动备份仅包含 localStorage，无法恢复任务和专注记录。现在导出及导入前备份包含原业务表、计时会话和本地设置。

导入前检查应用标识、备份版本、必需数据表、记录 ID、重复 ID、专注时长、设置类型以及计时会话格式。旧版完整备份仍受支持；只有设置的旧式自动备份会被拒绝，避免覆盖完整数据库。

浏览器下载动作已实现，但程序不能保证用户最终把下载文件保存到了期望位置，提示会要求检查下载结果。

### 3.2 原子导入及跨存储恢复

所有业务表在同一数据库事务中替换，写入错误会报告失败，不再被转换成成功。

IndexedDB 与 localStorage 无法使用一个原生事务同时提交。因此采用数据库中的持久化导入日志保存目标设置和原始完整快照：

- 数据库写入成功后应用设置。
- 设置写入失败时恢复原数据库和原设置。
- 导入途中页面关闭后，下次启动检查日志，继续完成或回滚。
- 维护期间设置数据库标记，旧业务管理器的写事务也检查该标记，减少与导入、重置互相覆盖的风险。

### 3.3 备份中的未结束计时

新版备份保留未记录完的专注区间。导入正在运行的会话时，将其变为待确认状态，并把可确认区间限制在备份生成时刻，不把备份生成后到今天的时间算作专注。

从备份恢复的确认框默认不勾选继续计时。旧版备份没有计时会话表时，不创建运行中的会话。

### 3.4 启动误删与重置竞态

移除了“localStorage 的 `Version` 缺失或为零就删除 `PomodoroDB6`”的启动路径。

重置操作现在等待数据库与设置处理完成后再返回成功，并生成完整备份。修复了数据库仍在清除、应用却已经刷新或提示成功的竞态。

## 4. 其他已实现修改

### 4.1 主题保存失败

主题写入失败会向上传递错误并显示提示，失败的主题不会被当成保存成功后激活。

增加主题 JSON 总量限制，允许已有超限数据通过删除逐步缩小。图片压缩失败时不再回退保存未经压缩的大图。

**仍采用 localStorage 保存主题图片；将图片整体迁移至 IndexedDB 尚未实施。** 当前修复集中在错误传播、限制体积和避免失败后激活。

### 4.2 外部请求边界

- 使用解析后的精确主机名判断 Bing 白名单，避免域名子串匹配绕过。
- fetch 对字符串、URL 与 Request 输入统一处理。
- 为页面增加 CSP，限制连接、图片、字体、媒体等来源。
- 停用旧主同步入口，移除已定位的图片形式遥测发送点。
- 保留 Bing 壁纸的明确允许来源，因此不能把此版本描述为“完全没有任何外部资源功能”。

### 4.3 音频与冗余补丁

浏览器测试发现原静音音频解码产生未处理异常。音频接入改为有错误处理的 HTMLAudio 播放，静音模式不再加载循环静音音频。

去掉评分弹窗补丁中的 React 内部树遍历与高频重复设置，改用现有偏好开关。

### 4.4 本地启动

增加 `scripts/server.cjs`，仅绑定 `127.0.0.1`，禁用缓存，避免依赖 npm/http-server；`start.ps1` 先切换到项目目录，然后优先使用这个服务器。

该变更源于验收环境中全局 npm 命令失效。测试直接使用 node 执行，没有修复或更改用户的全局 npm 安装。

**新增生产启动脚本及音频 Range 请求尚未完成独立验收，见未完成事项。** 浏览器集成测试使用测试文件内的临时 HTTP 服务器。

## 7. 当前使用与后续处理建议

当前代码可以继续评估，但应将其视为阶段性修补结果，而不是已经完成所有回归的正式发布。

数据库升级实际发生在打开新页面时。第一次在实际数据上使用前，建议保留一份完整旧备份，并关闭旧标签页，避免旧数据库连接阻挡升级。

数据库结构已经计划升级到 v3；不能认为把旧 JS 文件覆盖回来就能无条件回退。旧代码显式打开 v2 数据库时可能遇到版本错误。回退需要兼容的恢复方案和完整备份，不应通过删除数据库解决。

后续优先顺序：补齐普通完成通知与组件清理；验证跨标签页统计及音频恢复；验收生产启动脚本；最后进行真实睡眠/杀进程、长时间运行和完整报表奖励回归。
