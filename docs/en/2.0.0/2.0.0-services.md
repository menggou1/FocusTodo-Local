## Compatibility matrix

| Combination | Tested result / condition |
|---|---|
| Candidate peers with native locks/broadcasts | No duplicate focus writes; peer snapshots refresh. One automatic background owner, then immediate lock handoff on suspension. |
| Candidate peers without either capability | IDB serializes timer writes; a live maintenance transaction cannot be stolen by timeout. Peer startup waits, then recovers after owner closure. Polling refreshes tasks. Automatic background audio is disabled; manual effects/audition remain. |
| Interrupted import/quota/rollback | Post-row recreation completes settings; failed settings restore original rows/settings; failed rollback retains its decision. Three-engine owner closure and Chromium renderer crash are tested. |
| Fixed B client with C storage | Original B isolation rejects startup in all three engines. |
| Legacy production/unknown database with candidate | Startup rejects without changing sentinel data. The factory rejects the real DB name before open. Direct shared production writers are unsupported. |
| Synthetic v2 to v3 | Blocked upgrade rejects immediately; pending requests cannot silently upgrade later. New-instance retry retains rows and completes schema. |
| v4 schema or protocol 2 | Open/write is refused without deleting storage. |
| Same C implementation/protocol 1/schema 3 with 1.x/2.0.0 naming | Round trip preserves data, unknown fields and old read values, updating unread status for the current version. This is naming continuity, not arbitrary future binary downgrade support. |
| v1/v2 backups, DB2/3, JSON/Gzip | Synthetic matrix and ten authorized historical files pass normalized data/settings comparisons. No daily browser profile is used. |
