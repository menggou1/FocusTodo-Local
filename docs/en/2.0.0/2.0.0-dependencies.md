Vite and its React plugin declare Node `^20.19.0 || >=22.12.0`. The existing Node 22/24 test series remain appropriate, with **22.12.0** as the skeleton's minimum Node 22 minor version. The plugin accepts Vite `^8.0.0`. Its Compiler/Babel/Oxc peer dependencies are optional; the default configuration does not need additional direct compiler packages.

TypeScript 7 provides a stable native `tsc` executable. Its official announcement explains that 7.0 has no programmatic compiler API; the skeleton uses CLI checking separately from Vite transformation. The [TypeScript installation guide](https://www.typescriptlang.org/download/) also distinguishes transformation from checking.

## State, browsers and debugging

Navigation uses explicit state; React state/reducer/context handles UI state. Services own snapshots, asynchronous commands and subscriptions. The skeleton does not require Redux, a router, React Compiler or server components. Transactions and timer lifecycles remain service responsibilities; future complexity should be assessed from actual event ordering.

The [Vite production guide](https://vite.dev/guide/build) lists Chrome/Edge 111, Firefox 114 and Safari 16.4 as its default minimum targets. Explicit configuration avoids accidental changes after tool upgrades. Syntax transforms do not supply missing Web APIs; application capability checks still govern storage, locks, broadcasting, compression and notifications.

The isolation contract also requires `indexedDB.databases()` to enumerate existing databases. Missing support blocks startup; the prototype never probes cleanliness by opening a database. [MDN compatibility data](https://github.com/mdn/browser-compat-data/blob/main/api/IDBFactory.json) records Firefox support from version 126, so the Firefox 114 syntax target is not the candidate's minimum runtime version. Firefox 114–125 fails the capability check. Build targets and runtime capabilities are recorded separately.

The [development server](https://vite.dev/guide/) uses `esnext` and more recent browser capabilities. Acceptance therefore loads production output in Chromium, Firefox and WebKit. Real Safari acceptance remains V02. Relative `base: './'` supports HTTP root/project paths and extracted portable directories; ESM is not promised to run from `file://`. Offline acceptance blocks external traffic while serving complete local resources. Without a service worker, uncached remote addresses are not guaranteed to work without a connection.

Vite generates hidden sourcemaps; the build moves maps and its internal manifest to `dist/standalone/debug/` for private debugging. `dist/standalone/site/`, the candidate server and both portable archives exclude maps. Loading failures provide a retry path and never justify clearing storage.

## License, maintenance, security and size checks

Browser runtime dependencies include React, ReactDOM and its `scheduler` dependency. Candidate output includes their complete installed license files, preserving copyright and permission notices. The B prototype excluded historical fonts, images and audio. C reuses local audio, the application icon and catalogs; see the [C report](2.0.0-services.md). E17 still governs per-asset notices for final distribution. Root `package.json` now declares MIT consistently with the existing `LICENSE`, correcting its ISC metadata without rewriting copyright texts. This decision does not complete E17 for all historical assets.

Vite, the plugin, TypeScript and type packages are development tools; browsers and portable packages do not receive node_modules or their executables. Distributing tooling or additional runtime libraries requires checking the actual license/NOTICE files and dependency graph again.

Selection rests on stable official releases, locked installation, the Node contract and prototype results. The [Vite maintenance policy](https://vite.dev/releases) identifies 8.3 as the regular-patch series at this check. Updates include the lockfile, `npm ci`, checking, builds and browser/extracted-package acceptance; versions do not automatically track `latest`.

Security checks use `npm audit --json` against the installed graph and official advisories, recording date, scope and result. An empty scan does not rule out unknown vulnerabilities. The development server binds to loopback; built output requires no CDN.

Size evidence measures final HTML, JS, CSS, fonts, notices and other assets in raw/gzip bytes and records ZIP/tar.gz sizes. Cold start, language switching, optional-resource failures and dynamic imports use the same build. Debug maps are counted separately. node_modules size and advertised build speed are not user download or startup measurements.
