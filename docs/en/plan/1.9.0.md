# Version 1.9.0 plan

[Plans](README.md) · [Backlog](../BACKLOG.md) · [Maintenance](../MAINTENANCE.md)

Preserve existing data and behavior while improving wallpaper reliability, cross-tab theme ownership, mini timer capability detection and core experience checks. Progress belongs only in BACKLOG; no fixed delivery date is promised. Application versions remain `7.1.1-local.1.9.x`, with `1.9.x` tags. Independent versions start at 2.0.0.

| Priority | Scope | Acceptance | Backlog |
| --- | --- | --- | --- |
| P1 | Wallpaper requests and fallback | HTTPS Bing image hosts, controlled requests and redirects, CORS/timeout/cache/day-change/offline fallback, saved themes | E14, V05 |
| P1 | Basic cross-tab theme ownership | Conflict detection or explicit ownership beyond single-operation rollback and startup recovery; timeouts must never authorize takeover | E02 |
| P2 | Browser mini timer | Prefer Document Picture-in-Picture; read-only display with start/pause/stop through the existing adapter; in-page fallback without promising system-level always-on-top | E11 |
| P2 | Core experience and degraded capabilities | Tasks, timer, schedule, history and reports; Chinese/English, light/dark, widths, keyboard, reduced motion; no BroadcastChannel/Web Locks/compression API | V02, V03, V04, V06 |

Excluded: independent versions (E16, 2.0.0), full IndexedDB image migration (E01), new backup container (E03), comprehensive large-package optimization (E04), full component source recovery (E09), cloud sync, groups and online rankings.

## Sequence and acceptance

1. Review 1.8.3 and backlog gaps; use isolated data and old backups containing images, timer sessions and schedules, with rollback guidance.
2. Implement request boundaries and theme ownership, with unit and browser coverage.
3. Add mini timer detection and fallback; verify Chromium first, then Firefox/Safari fallback.
4. Check the core experience and gather available real-environment evidence.
5. Freeze scope, run complete regression and portable-package checks, document upgrades, merge into main and publish through the maintenance workflow.

Require generation consistency, units, syntax, full browser checks, three operating systems with Node 22/24, extracted ZIP/tar.gz startup and documentation links. Verify old imports, cross-tab changes, interrupted timer recovery, offline use and theme switching. Test wallpaper success, failures, timeouts and day changes. Mini windows must not create another tick loop or persistence path. Keep database, preferences, sessions, release-read state and history. Keep remaining acceptance gaps only in BACKLOG and completed evidence in the release report.

Reuse data services, the timer adapter, shared controls and maintenance locks; keep database v3 and the 1.8.x visual baseline except for explicit requirements. Preserve old backup compatibility and document rollback limits. Publish through `release.json` → `build:release` → CI → tag `1.9.0` → Release → Pages.
