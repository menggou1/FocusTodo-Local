# 2.0.0 Phase D first batch: workspace and tasks

[Maintenance](../MAINTENANCE.md) · [Roadmap](2.0.0.md) · [Frozen contracts](2.0.0-service-contracts.md) · [Open work](../BACKLOG.md) · [中文](../../plan/2.0.0-ui-batch-1.md)

Verified 2026-11-08 (Asia/Shanghai), based on local unpushed commit `6d3512c` on `refactor/standalone-app`. This batch connects the D01/D02 base workspace and associated D08/D09 behavior. The visible app now uses isolated persistence rather than B's in-memory sample. C service implementations and v1 contracts remain unchanged. Production entry/version, Pages and ordinary packages are unchanged; the branch is neither merged nor pushed.

## Delivered behavior

| Area | Implementation |
|---|---|
| Shell/navigation | 50px header, preference-driven sidebar (280px default), preset views, folder collapse, search and later-view entries. Narrow navigation works with details open; keyboard navigation focuses the view heading. Language/dark mode subscribe to core preferences. Startup no longer calls B's sample adapter. |
| Lists/folders | Create, rename, folder assignment, visibility, deletion confirmation, same-group pointer/keyboard ordering and default preset order restoration. Commands retain C transaction semantics; list reorder submits its original order snapshot. |
| Tasks/search | Creation, title, project, due date, reminder, priority, estimates, duration, notes and recurrence fields; completion/undo, deletion with history retention. Search uses C task/note/subtask queries. Recurring completion and child copying remain C transactions. |
| Subtasks | Creation, editing, completion/undo and confirmed deletion, preserving associations/compatible fields. |
| Task order | Pointer/arrow-key moves use a single `updateTask` with original-value checks. Exhausted order slots reject with conflict feedback. This does not promise an atomic multi-task reorder snapshot. |
| Errors/focus | UI subscribes to committed snapshots. Drafts retain their opened revision and stale saves reject rather than overwrite. Only edited fields are submitted, preserving unknown fields and sub-minute reminder timestamps. Failures retain input; incompatibility/recovery requirements stop writes and offer reload. Native dialogs support Escape and return focus; completed async commands restore focus lost to disabled controls. |
| Local resources | Existing list icons and Noto Sans / Noto Sans SC; swap fallback keeps failed fonts nonblocking. Full OFL text is included in candidate `licenses/`. E17 still governs other distribution notices. |

Components receive `ApplicationServices` with the repository physically omitted. They do not write IDB/localStorage directly or depend on legacy Redux, DOM selectors or `Focus*` globals. Services continue owning timers, reminders, broadcasts and resource lifecycle.

## Verification

Run `npm run build:standalone`, `npm run package:standalone`, `npm run test:standalone`, `npm test` and `npm run check`. `npm run test:workspace` reruns this UI batch against an existing build.

The workspace suite operates the production candidate at a random loopback project subpath with fresh contexts, generated data and external networking blocked. It covers fields, subtasks, search, completion/undo, reload, lists/folders, pointer/keyboard ordering, recurrence, quota retry, two-tab conflicts, incompatible-write blocking and preservation of unknown fields/reminder precision. Chinese/English × light/dark compare A header/sidebar geometry and cfd6449 typography/line-height/heights; injected 30px typography must fail the assertion. A 375px viewport checks clipping/navigation/focus. These partial checks do not establish whole-view visual parity.

Actual results/environment are in the [evidence summary](../../acceptance/2.0.0-d1/summary.json). New output goes to `dist/acceptance/`; selected synthetic summaries/screenshots are archived under `docs/acceptance/2.0.0-d1/`. Test globals/fault injection stay out of product packages. Both extracted archives check local offline resources, project subpath, task creation and reload persistence.

## Acceptance boundary

This is functional integration with partial visual comparison, not completion of all D01/D02 requirements or D exit. Details currently use an explicit-save draft form; header actions, summary layout and other details still visibly differ from the legacy baseline. Those differences are not treated as user-approved. Remaining scope and interaction/visual work live only in BACKLOG E09.

WebKit is not real Safari. Synthetic lifecycle/fault tests and automated downloads do not replace real systems, daily profiles or manual experience; V02–V07/F define those checks and comparable performance. The actual release remains `7.1.1-local.1.9.3`, schema v3 and backup format are unchanged. Remote CI has no new result before a push.
