## Run the preview

```powershell
Set-Location D:\document\projects\Focustodo-dev
# Fresh clones first run npm ci
npm run build:standalone
npm run preview:review
```

Open **http://127.0.0.1:5512/**. Stop with `Ctrl+C` in the server terminal. Keep the same hostname, port and browser profile to retain review data. If occupied, leave unknown processes alone; use `npm run start:standalone` for a random port or `node scripts/standalone-server.cjs --port 5513`. Each port has separate data. The candidate CLI excludes production port 5500.

The branch is `refactor/standalone-app`. Only namespaced candidate storage is used: `FocusTodoStandalone.PomodoroDB6` v3, its lock DB and `FocusTodoStandalone.data.` settings. External networking defaults off. Cloud accounts/sync, groups and online rankings remain outside the agreed scope.

For portable review, run `npm run package:standalone`, fully extract `dist/standalone/FocusTodo-standalone-prototype.zip` or `.tar.gz`, and run `node start.cjs`. Open the printed random address. npm dependencies are unnecessary in the extracted package. These are engineering artifacts, not a 2.0.0 Release.

## Review with data

[demo.json](../../acceptance/2.0.0-dr/demo.json) is generated by `node tests/fixtures/create-review-demo.cjs`. It contains explicitly synthetic projects/folder/tag, eight tasks, three subtasks, 28 focus records and three schedules dated relative to generation. No private data or real avatar is included. The same file is `DEMO-REVIEW.json` inside both engineering packages.

Open Settings → General → Import data, choose the file and confirm replacement of isolated data. The candidate downloads the current complete backup first, then asks whether it has been saved and is readable. Canceling preserves existing data. After importing, close Settings and inspect tasks, Schedule, Reports, Forest and Completed/history. Demo schedules occur around 09:00–12:00 on generation day; scroll the time grid. Starting empty and creating tasks is also supported.

## Observed differences and evidence limits

These describe this candidate, not accepted visual restoration. Current difference status and user feedback belong in BACKLOG E09.

- Fonts, icons, controls, colors, spacing, overlay dimensions and narrow layouts differ. Date/time/numeric/recurrence controls are operable native inputs. Settings, Reports, Forest and timer cover the workspace and return on close; exact interaction fidelity still needs user comparison.
- Reports use SVG duration/task stacks, numeric/proportional distribution and a goal calendar. Chart geometry, legends and timeline markings differ. Period controls, values and associations work; the charts are not placeholders.
- Forest uses original tree/background images, with different sunlight placement, collection/growth animation and achievement presentation. Actual rewards and collections persist.
- Restore/reset explicitly confirm receipt after downloading a full backup. Avatar upload supports PNG/JPEG/GIF under the existing 512 KB data-URL bound.
- Actual milliseconds and UTC offsets are retained; real interval splitting may differ from the old DST display defect recorded in A.
- Native mini windows depend on Document Picture-in-Picture, with an actionable main timer fallback. Notifications require permission; background audio depends on browser policy/Web Locks. Real Safari, system media and actual long-lived profiles are not certified by local automation.

Reproduce with `npm run build:standalone`, `npm run package:standalone`, `npm run test:standalone`, `npm test` and `npm run check`. [Evidence summary](../../acceptance/2.0.0-dr/summary.json) records counts, engine versions, build metrics and screenshots. Only generated data and isolated contexts/origins are used. Both packages are extracted into Unicode/space-containing paths and started without npm/Git.

Suggested review order: tasks/lists, timer/audio, all calendar views, history/reports, forest/achievements, every settings section, notifications/updates; switch language/theme too. Feedback can identify the page/entry, old behavior, candidate behavior and reproduction steps. Codex records the differences and follows explicit feedback without inferring D-V authorization from silence or test results.
