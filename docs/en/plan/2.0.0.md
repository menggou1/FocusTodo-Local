# Version 2.0.0 plan

[Version plans](README.md) · [Backlog](../BACKLOG.md) · [Maintenance](../MAINTENANCE.md) · [中文](../../plan/2.0.0.md)

Enable independent version numbers while preserving data and behavior across tasks, timer, calendar, reports, forest, achievements and backups. This plan defines scope and acceptance; Backlog alone tracks progress. No fixed release date is promised.

## Scope and priority

| Priority | Scope | Acceptance | Backlog |
|---|---|---|---|
| P1 | Independent versions | Application version and tag are both `2.0.0` starting with this release. Keep 7.1.1 only as provenance metadata. Generation, display, history, packaging, deployment and release gates agree; historical versions and tags remain unchanged | E16 |
| P1 | Upgrade and data compatibility | Read 1.x backups without resetting databases, preferences, timer sessions, notification reads or history. Document compatibility and downgrade limits | E16, V07 |
| P2 | Wallpaper request boundaries | Enforce request and redirect restrictions. Verify cross-origin failures, timeouts, expired/cross-day caches and offline fallback while preserving saved themes | E14, V05 |
| P2 | Core experience and capability fallback | Check tasks, timer, calendar, history and reports; cover Chinese/English, light/dark, multiple widths, keyboard, reduced motion and browser capability fallback | V02, V03, V04, V06 |

Resource tables, a new backup container and large-backup optimization (E01–E04) are not automatically included. Add them only with clear benefit, compatibility design and verification capacity. Full component-source recovery (E09) remains separate. Cloud accounts, cloud backups, cross-device cloud sync, groups and online rankings are excluded.

## Implementation order

1. Check delivered 1.8.1 behavior and actual gaps. Set release scope in Backlog; prepare isolated data, older backup samples and downgrade guidance first.
2. Complete E16: update version metadata and generators, display, historical recognition, cache, packaging, deployment and release checks, then verify old/new versions and backup compatibility. This 1.8.1 release still uses `7.1.1-local.1.8.1`.
3. Complete scoped E14/V05 network boundaries and fallback work. Address confirmed usage gaps with existing data services, timer adapters and shared controls.
4. Freeze scope, complete regressions and extracted-package acceptance, write upgrade guidance, then merge to main, push, deploy and release using the maintenance procedure.

## Acceptance records

- Pass generated-file consistency, unit, syntax and full browser checks; Windows/macOS/Linux × Node 22/24, ZIP/tar.gz extracted startup and documentation links.
- Use isolated data to verify old-backup import, cross-tab operation, interrupted-timer recovery and offline operation. Real sounds, notifications and long-lived databases require matching environment evidence; stubs and simulated clocks do not replace it.
- Verify same-commit main, tag, Pages and Release, the live `deployment.json`, project-subpath startup, application display and downloadable version identities.
- Track gaps and unfinished verification only in Backlog. Remove completed items after evidence exists and record results, compatibility and evidence in the final release report.
