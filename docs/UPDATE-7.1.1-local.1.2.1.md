## 修复内容与原因

修复多个标签页同时打开时，部分页面任务进度及专注统计未及时刷新的问题。此前在 macOS CI 偶发出现，但通过控制初始化顺序，也在本地 Windows 稳定复现，因此它是跨平台初始化竞态，不是 macOS 独有的计时规则问题。

原计时适配器在等待首次 tick 和界面渲染完成后，才订阅 `focus-local-timer-changed`。另一页恰在此期间提交专注记录时，BroadcastChannel 已收到并转发事件，但计时器尚无监听器，导致该页漏掉记录刷新事件。数据库中的记录仍已保存，问题在该页的界面和统计刷新。

`js/local-timer-ui.js` 现改为初始化开始时先订阅事件，并沿用现有 Promise 队列，将收到的记录刷新排在首次 tick 后执行。处理前等待数据初始化并检查卸载/维护状态，保持串行处理和原有监听器清理。没有改变计时结算规则、数据库结构或备份格式。

## 回归与验证方法

新增一个可控时序的浏览器用例：暂停另一页首次 tick 返回后的初始化，让主页面在此时提交跨越两个番茄的记录；确认另一页确实收到全部广播后，再恢复初始化，并同时检查记录事件、记录 ID 和任务进度。

修补前稳定观测到广播收到 **3 条记录**、界面记录事件 **0 条**；修补后断言收到的记录 ID 与提交结果完全一致，任务进度同步更新，不丢失或重复。记录可能由多个有效片段组成，因此按实际提交 ID 验证，而非假定每个番茄只对应一条记录。等待同时覆盖异步记录事件与任务进度完成，没有删除原用例断言或提高其超时来掩盖失败。

原跨标签页刷新用例保留，并在失败时输出独立测试数据中的会话、记录和任务状态，便于以后定位。浏览器验收共 **44 项**。

本地两个跨标签页用例连续 **3 轮通过**，核心、HTTP 和启动器测试通过，语法检查通过。临时远程分支仅用于 macOS / Node.js 24，执行完整浏览器验收及 **5 轮**两个跨标签页用例，并检查两种压缩包解压运行。正式发布仍使用三系统 Node.js 22/24 的完整验收门禁，结果见对应 Actions 记录。
