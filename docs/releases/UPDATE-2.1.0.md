# FocusTodo 2.1.0

[更新记录](../CHANGELOG.md) · [English](../en/releases/UPDATE-2.1.0.md)

2.1.0 累计更新至 2026-11-19，CI #152 修复以远程 dev `25c537f41380da583dea6524a824d265e7fa0eb5` 为基线。最新正式版本为 2.0.2。

## 设置与数据

任务完成提示音沿用备份和旧版兼容键 `TskCmpSnd`，默认开启，继续共用 `RtnVol`。任务提交成功后才发出效果音。音量拖动期间实时调整已有试听及白噪音音量，手势确认后才播放一次反馈。两个铃声下拉菜单把「无」放在首位，保存值和默认值继续按原标识读取。

头像随现有 JSON/Gzip 设置快照恢复，并在恢复后从资料服务刷新各显示位置。导入与通知复用共享滚动条，中断确认使用共享确认弹窗。日程工具栏位于已展开的通知下方，更新详情按钮使用双轴居中。

任务右栏底部常驻图标恢复为 24×24。到期日沿用归档版的中英文相对日期及星期格式，只有早于当天的日期显示红色。设置文案改为「新任务添加至其他任务上方」，沿用原排序逻辑。

通用设置依次显示「语言」下拉菜单和新任务排序开关。「通知」与「功能开关」共用分节样式，桌面通知使用行内按钮。任务完成提示音集中在番茄钟设置的「提示音」中，已有选择和备份兼容键继续生效。

专注森林的一键收取按钮实时排除已收取的阳光，避免收取动画结束时短暂恢复高亮。选用 Bing 每日壁纸且启用外部联网时，启动后及运行中自动检查缓存有效期，跨日或到期后更新图片。下载失败时保留缓存，切换到其他主题后，之前启动的自动刷新无法覆盖新选择。

## 启动与图标

沿用 1.9.4 按实际完成事件计数的做法。新界面统计脚本、样式、本地数据、字体、图标、声音和工作区提交。失败或超时停留在可重试界面，便携版资源由本地服务提供。工作区进入动效尊重减少动态效果设置。支持 Web Audio 的浏览器使用内嵌的原始 WAV，避免 IDM 截获独立请求。Windows WebKit 等仅支持原生媒体播放的环境读取同字节本地资源。

通知、启动界面及浏览器标签页共用归档版 30×30 的 `8fzlr-o0m4w-001.ico`，改名为 `focus-app.ico`。

增加了更清晰的图标。

Vite 开发预览为启动图标和网页标签图标提供可读取的资源地址，正式和隔离打包继续使用相对路径。Windows 可运行 `./scripts/preview-standalone.ps1` 启动隔离预览，默认使用 5511，端口冲突时可通过 `-Port` 指定空闲端口。

## 开发验证

macOS Node 24 的浏览器合同曾在两个标签页竞争音频锁时假定固定获胜者。用例先建立持锁页，等待对端真正进入 Web Locks 队列，再验证独占播放及交接。[失败作业](https://github.com/menggou1/FocusTodo-Local/actions/runs/44247634654/job/134610681204)

CI #150 的 Ubuntu／Node 24 作业在获取 Firefox 和 WebKit 的系统依赖时超时。该作业使用与锁定 Playwright 版本匹配的镜像，预装三个受测引擎和系统依赖。作业时限为 30 分钟，给冷拉取镜像预留余量。[超时作业](https://github.com/menggou1/FocusTodo-Local/actions/runs/44270097521/job/134684709745)

CI #151 的容器作业在构建时遇到 Git 工作区所有权检查。作业先核对工作区路径和检出的提交，再为本作业内的 Git 命令设置该路径的 `safe.directory`。[失败作业](https://github.com/menggou1/FocusTodo-Local/actions/runs/44290847746/job/134755704275)

CI #152 的 Ubuntu／Node 24 容器以 root 启动 Firefox，却继承了其他用户拥有的 `/github/home`。Firefox 和 WebKit 的两组步骤使用容器内的 `/root`。[Ubuntu 作业](https://github.com/menggou1/FocusTodo-Local/actions/runs/44294563193/job/134768486798)

macOS／Node 24 的任务详情对照等待两侧显示本次选中的任务，再读取到期日和颜色，并核对刷新后的固定时刻与时区。[macOS 作业](https://github.com/menggou1/FocusTodo-Local/actions/runs/44294563193/job/134768486830)

Windows／Node 24 的历史归档验收在进入壁纸备份步骤前停在 `0 / 19`。启动失败时会记录浏览器异常、控制台、资源状态和请求错误，供 CI 日志和验收附件定位具体阶段。[Windows 作业](https://github.com/menggou1/FocusTodo-Local/actions/runs/44294563193/job/134768486864)

跨平台的 Chromium 回归步骤显式使用会传递中间命令失败状态的 shell，确保单个脚本失败就能阻止门禁通过。
