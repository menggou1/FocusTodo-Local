# 7.1.1-local.1.8.2 更新报告

## 初始问题

森林入口只在森林窗口关闭后刷新红点，界面未打开时仍显示旧记录。森林缺少一键收取，语言使用浏览器原生下拉而其他设置使用应用下拉，控件样式分散，后续版本命名和实施安排需要明确。

- 计时快照只对专注时长使用核心规范化结果进行校验。缺失或无效的短休、长休、长休周期和自动切换选项仍能进入覆盖导入，例如零休息时长或字符串 `"false"`；恢复后会改变休息和自动切换行为。
- 本地服务将解码后的 NUL 字符传给 `fs.realpath`，产生未捕获的同步异常。隔离子进程发送 `GET /%00` 后连接重置，服务以状态 1 退出。
- 英文日程当天标题缺少 `今天` 的精确翻译，出现 `This content is unavailable in English.`。此项原已记录为 E13。

## 最终行为

- 森林入口独立更新可收取阳光数量，覆盖首次加载、成熟与过期、数据变更及跨标签刷新。
- 手形一键收取复用现有收取服务和圆形入口样式，成就、攻略使用同一按钮规则。
- 全体样式纳入审计与重构范围，按基础、共用控件及功能布局整理职责；侧栏、任务、计时、设置和独立页面均纳入梳理。共用按钮、设置开关、番茄图标、日期和下拉控件提取复用，语言菜单与其他设置菜单一致；样式结构调整默认保持现有视觉及交互。
- 确定从 2.0.0 起使用独立三段式应用版本，Tag 同步使用本地三段数字；官方 7.1.1 只作为来源信息保留。本次仍为 `7.1.1-local.1.8.2` / Tag `1.8.2`。工程计划按实施顺序、兼容要求和验收条件单独维护。
- 导入配置的每个核心字段必须与计时核心的规范类型和取值范围一致，在申请维护锁、覆盖数据或修改设置前拒绝无效快照。合法配置、v1/v2 无计时快照的备份及暂停休息保持兼容。
- 本地服务在访问文件系统前拒绝 NUL 路径，对 GET/HEAD 返回 400，后续正常请求继续返回 200。
- 在 `i18n/local-en.json` 补充 `今天 → Today`，通过既有生成器同步词库；日程布局和旧主包无需修改。

1.8.0 候选未生成 Release：Ubuntu 的控件验收把按字体自动计算的下拉文字宽度与 Windows 基准直接比较。现改为检查文本是否完整容纳在下拉框内，继续校验控件尺寸、字体、颜色和交互。Tag 门禁复用同一 main 提交的测试和 Pages 部署结果。

启动页内联检查比较实际内容，兼容 Git 在 Windows 检出时使用的 CRLF 换行；样式或脚本内容有差异时仍会失败。
导入回滚验收先等待森林写完当日登录奖励，再完整比对原设置，避免把后台初始化写入误判为回滚失败。
