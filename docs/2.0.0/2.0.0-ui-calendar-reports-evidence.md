## 已取得的实际证据

专项脚本：`tests/standalone/visual-calendar-reports.cjs`。输出：`dist/acceptance/calendar-reports-restore/`，包括 `metrics.json`、新旧截图、`*-compare.png`、`*-diff.png` 和 `pixels.json`。

最新中文亮色运行实际采集了 11 个场景：空日/周/月、空报表、快速任务、手动记录、时长下拉、含数据报表、底部柱图、含数据日视图、安排详情。所选主要边界和字体/颜色断言均为 **0 项差异**。这没有覆盖每个子元素；时长下拉目前主要保留像素证据。

此前一次完整专项运行还验证了：合成记录总量为 50 分钟、15 期小时轴末期为 0.83、最小纵轴为 4、周期切换、双事件列、键盘 resize 实际增加 300 秒，以及数据库重载后仍保留该安排。新客户端没有请求旧主包或安装旧运行全局。13px 人为平移反例能够使几何检查失败。

最新扩展运行在完成 11 场景采集后，因测试清理错误停止：旧安排详情关闭后已经自动关闭任务面板，脚本又尝试点击不存在的任务面板关闭按钮。该假设和候选关闭行为已修正，**修后尚未重跑完整专项**。因此旧 `results.json` 不是最新 11 场景的全量完成凭据；最新采集以 `metrics.json` 和对应截图为准。

## 已确认的参照缺陷例外

用户已明确选择保留正确日期。旧 2026 年 11 月目标日历首周的组件 `goalInfo` 实际生成了 `24,25,26,27,28,29,1`；同月日程视图显示的真实上月日期为 `26,27,28,29,30,31,1`。候选保留真实本地日期及对应记录映射，不修改底层时间戳来复制错误标签。此项应在最终对照中单独说明，不能据此放宽其他视觉差异。
