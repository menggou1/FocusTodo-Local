# 2.0.0 开发与验证依据

[计划](../plan/2.0.0.md) · [当前待办与验收](../BACKLOG.md) · [维护指南](../MAINTENANCE.md) · [基线审计](2.0.0-audit.md) · [服务合同](2.0.0-service-contracts.md)

本页归并 2.0.0 开发过程中的主要结论。以下测试结果是对应日期的历史证据，不代表当前版本已通过完整验收；未完成事项及人工验收状态只在 BACKLOG 维护。更细的逐轮记录可从 Git 历史查看。

## 基线和隔离

旧版对照使用 1.9.3 运行文件；最初审计基线为 `f102da8`，后续也核对过 Tag 1.9.3 的运行文件。新旧运行时对照使用隔离的 5513 和 5511、独立浏览器上下文及合成数据，不使用日常 Profile。不同轮次的视口、负载、浏览器和采样方式不同，性能数据不能直接互相比较。A 阶段的存储、功能、依赖、备份及许可取证保留在[基线审计](2.0.0-audit.md)，历史截图位于 `docs/acceptance/`；临时测试结果默认位于 `dist/acceptance/`，可能已被清理或覆盖。

## 独立工程与服务

候选采用 React、TypeScript、Vite 和显式服务，正式旧入口、Pages 与普通便携包没有切换。服务通过独立数据库和设置命名空间隔离；备份仍使用旧逻辑键与 v3 元信息。启动时检查隔离和协议，依序恢复数据库及主题日志、设置、计时和业务状态；无法确认兼容时拒绝写入。接口边界及兼容增补见[服务合同](2.0.0-service-contracts.md)，实际开发命令和存储约束见[维护指南](../MAINTENANCE.md)。

2026-11-08 的服务验证覆盖计时纯核心差分、事务故障恢复、旧备份导入、主题、网络及并发隔离；10 份获授权历史备份在内存比较通过。三引擎检查过候选并发、旧客户端拒写及不兼容 schema/protocol 拒写。相同 schema 和协议下的版本命名往返不证明任意版本可降级，真实 Profile 原地升级仍需按 BACKLOG 验证。

## 界面与交互

- 初期 D-R 人工审查未通过，之后获授权逐页面主动对照旧版。保留独立源码和服务架构；自动化结果不等于用户视觉验收。
- 2026-11-10 的 D-R4 对日历和报表记录了 44 组截图对照、4/4 overlay、三引擎领域测试及日历→计时→报表场景。覆盖范围内通过不表示所有尺寸、动画和真实系统体验已通过。
- 计时器、森林及工作区的 D-V 对照覆盖明暗、中英文、局部几何、指针操作和动画；森林成就列表按用户要求使用 ScrollView，是明确允许的旧版差异。统一文字选择和装饰图片拖动机制曾在三引擎验证，保留输入及可复制内容的选择和合法拖拽。
- 工作区 W1–W7 验证过快速添加、侧栏统计、日期排序、详情栏及重复/提醒/子任务等持久化，包含跨页面操作。2026-11-15 又检查了主工作区两种视口和中英明暗组合，以及设置六页、拖动、主题和备份相关操作。
- 2026-11-15 设置专项记录类型检查和构建通过，单元测试 60/60、工作区浏览器测试三引擎 60/60、服务浏览器测试三引擎 31/31；Bing 使用可控网络响应，不能据此宣称真实外网验收通过。

局部性能采样曾发现计时小组件收展和森林动画仍有长帧；计时采样中新版为 Vite 开发预览，与旧版生产包的条件不同，不能据此归因或宣称性能等价。实际待修项、真实系统验证和人工审查以 [BACKLOG](../BACKLOG.md) 为准。

## 复验入口

构建与测试命令以[维护指南](../MAINTENANCE.md)为准。界面对照应固定旧版、数据、语言、主题、视口和缩放；使用独立上下文，记录运行环境、失败与结果边界。真实浏览器数据和历史备份不能用于破坏性试验。仓库测试入口包括 `tests/standalone/` 下的服务、工作区、领域页面和设置专项；历史报告中的临时脚本或截图路径不保证仍存在。
