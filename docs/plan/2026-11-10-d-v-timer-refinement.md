## 记录块的真实规则

依据 `src/js/main.js` module 1119、1120，`src/main.css` 的 TodayDetailItem 规则，以及运行时实际结果：

1. 按 endDate 索引升序取得本日截至当前时间的记录，范围下界包含、上界不包含；同一 endDate 按主键顺序绘制。跨日开始时间截到本日零点。
2. 块高为秒数 / 30，没有人为最小高度。小于 480 秒时色块保留，名称和时长为空。
3. 高度小于 33px：紧凑显示，去掉上下 8px padding，垂直居中，名称 clamp 为 1 行。
4. 高度大于等于 33px：普通显示，名称最多 floor((height-16)/17) 行；恢复旧版嵌套文本容器、ellipsis、max-height 和 overflow 裁切。
5. 旧版没有额外的“碰撞后丢弃整块”条件。超出滚动视口会被裁切；重叠时后绘制的块覆盖前块。完全覆盖的块仍在 DOM 中，但像素不可见。没有自行添加隐藏阈值或自动避让布局。

同一组数据包含 15、479、480、989、990、1020、1800、4500 秒、长名称、同时间完全重叠且大小写主键不同的块，以及过去/未来范围外记录。并加入恰好从零点开始、479.5 秒且不应被取整为 480 秒的边界块。旧新均绘制 10 个当前范围内块；紧凑状态、根及文本尺寸、时长、clamp、省略样式和遮挡命中结果一致。15 秒块仅 0.5px 高且无文字；480 秒块为 16px 紧凑显示；990 秒块为 33px 普通显示。重叠测试中前块被覆盖、后块可见，两边一致。

## 收展性能的证据与剩余差异

已移除记录无变化时的大 Canvas 重置。观察尾段 1.2 秒内，旧新记录 Canvas 的额外 width 重置次数均为 0；含收展重挂的全过程，旧版重置 12 次、新版 6 次。测量拦截 Canvas 原型，包含重新挂载后创建的实例。局部设置写入失败测试验证：视图回滚为展开，存储仍为 true，按钮 opacity 保持 1。没有更改按钮外观。

CPU 采样中，主要非空闲热点包括 Timer 内创建静态刻度的 jsxDEV；通过运行中的 Vite 转换代码定位到了 Array.from(120) 的对应调用，再实施缓存。`cpu-diagnostic.json` 保存采样及调用链。

最后一次同机、双方均运行、含录像的 Chromium 诊断：旧版最大帧间隔 24ms、超过 34ms 为 0；新版最大 48ms、超过 34ms 为 6。TaskDuration 分别约 0.656s / 0.966s。数据见 performance.json；这是单次本机诊断，不是稳定 FPS 承诺。仍有残余卡顿，不能宣称与旧版同样流畅，也不能在没有进一步证据时全部归因于浏览器。本轮到此保留问题，不修改全局上下文、其他组件或业务持久化策略。后续状态只在 BACKLOG E09 维护。
