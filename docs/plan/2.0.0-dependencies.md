## 状态、浏览器与调试

界面导航使用显式状态，局部状态用 React state/reducer/context；服务保留独立快照、异步命令和订阅接口。本阶段不引入 Redux、路由库、React Compiler 或服务端组件。状态方案的依据是骨架只需导航、语言、主题和服务连接；数据事务及计时生命周期由服务负责，后续功能复杂度须以实际事件顺序评估。

[Vite 生产构建文档](https://vite.dev/guide/build)的默认目标范围是 Chrome/Edge 111、Firefox 114、Safari 16.4 及以上。配置显式记录目标，避免将来工具升级暗改范围。语法转换不会补齐缺少的 Web API；IndexedDB、锁、广播、压缩、通知等仍由应用能力检测和兼容合同处理。

候选隔离合同还要求 `indexedDB.databases()` 能列举已有数据库；能力缺失时拒绝启动，不通过试开数据库推测来源是否干净。[MDN 兼容数据](https://github.com/mdn/browser-compat-data/blob/main/api/IDBFactory.json)记载 Firefox 从 126 支持此方法，因此 Firefox 114 的语法目标不是候选的运行最低版本。原型实际要求该列举能力，Firefox 114–125 会按合同显示启动失败；构建目标和能力要求须分别记录。

[Vite 开发文档](https://vite.dev/guide/)的开发服务器使用 `esnext` 和现代浏览器能力，不能以开发服务启动成功证明发布包兼容。验收加载生产构建，分别覆盖 Chromium、Firefox 和 WebKit；真实 Safari 的业务及声音验收继续按 V02，不用 WebKit 自动化替代。发布包使用相对 `base: './'`，从根路径、项目子路径和实际解压目录提供 HTTP 资源；不承诺 `file://` 打开 ESM。离线指外网阻断下本地完整资源启动；没有 service worker 时不承诺未缓存的远程地址在断网后可用。

Vite 生成 hidden sourcemap，构建脚本把 map 和 Vite 内部 manifest 移到 `dist/standalone/debug/`，用于私有调试；`dist/standalone/site/`、候选服务器和两个便携包均不包含 map。错误提示提供重试，不能因加载失败清空数据。

## 许可证、维护、安全和体积核对

新浏览器运行依赖包括 React、ReactDOM 和 ReactDOM 引入的 `scheduler`；其完整许可证从实际安装包复制到候选产物，保留版权及许可文本。当前骨架不打包旧字体、图片或音频；以后复用素材时继续附带各自许可文件。根 `package.json` 已按现有 `LICENSE` 将 ISC 元数据纠正为 MIT，未改写原版权文本。本次依赖核对不替代 E17 对旧应用所有分发素材的逐项核对。

Vite、插件、TypeScript 和类型包是开发工具，不作为浏览器脚本或 npm 依赖目录交付。若以后分发这些工具本体或新的运行包，需按实际分发内容重新核对其许可证、NOTICE 和间接依赖。不要把“顶层包声明 MIT/Apache”写成全仓库素材许可已完成。

维护选择依据为官方稳定发布、精确锁定、Node 合同及原型结果；[Vite 维护政策](https://vite.dev/releases)在本次核对时把 8.3 列为常规补丁系列。更新时同时提交锁文件、运行 `npm ci`、类型检查、构建及浏览器/解压包验收，检查上游迁移说明；不自动追随 `latest`。

安全核对使用 `npm audit --json` 的实际安装图，并检查官方安全公告；记录日期、范围和结果。扫描为零不证明没有未知漏洞，包许可证字段也不证明分发义务均已满足。开发服务器仅监听 loopback，不向局域网暴露源码和文件服务；构建不依赖 CDN。

体积证据从最终候选目录逐文件测量 HTML、JS、CSS、字体、声明和其他资源的原始字节及 gzip 字节，并记录 ZIP/tar.gz 大小。冷启动、语言切换、可选资源失败和动态 import 测试针对同一构建；调试 map 单独统计，不用 node_modules 体积或工具宣传的构建速度代表用户下载量和启动性能。
