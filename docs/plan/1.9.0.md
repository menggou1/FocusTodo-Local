# 1.9.0 版本计划

[版本计划](README.md) · [统一待办与验收](../BACKLOG.md) · [维护指南](../MAINTENANCE.md)

目标：在保持现有数据与行为连续的前提下，完成壁纸可靠性、主题并发安全、迷你计时窗口能力检测，以及核心体验与能力降级核对。本计划记录范围与验收标准，进度只在 BACKLOG 维护，不承诺固定发布日期。

版本格式继续使用 `7.1.1-local.1.9.x`（Tag 为 `1.9.x`）。独立三段式版本号留给 2.0.0。

## 范围与优先级

| 优先级 | 范围 | 完成标准 | BACKLOG |
| --- | --- | --- | --- |
| P1 | 壁纸请求边界与失败回退 | 图片地址限制为 HTTPS Bing 域名；请求与重定向可控；跨域、超时、缓存过期、跨日刷新、断网回退行为正确；已保存主题可用 | E14、V05 |
| P1 | 主题跨标签并发编辑归属（基础版） | 在单操作写入回滚与启动恢复之外，增加跨标签冲突检测或明确归属；不能用超时冒充安全接管 | E02 |
| P2 | 浏览器迷你计时窗口 | 优先使用 Document Picture-in-Picture；只读显示 + 开始/暂停/停止，命令走现有计时适配器；无 API 时回退页内浮动计时器；不承诺系统置顶 | E11 |
| P2 | 核心体验与能力降级核对 | 核对任务、计时、日程、历史、报表；验证中英、亮暗、多宽度、键盘、减少动态效果；无 BroadcastChannel / Web Locks / 压缩 API 时行为符合预期 | V02、V03、V04、V06 |

以下事项不纳入 1.9.0：独立版本号改造（E16 → 2.0.0）、主题图片完整迁入 IndexedDB（E01 仅可做准备）、新备份容器格式（E03）、大包主线程优化全面改造（E04）、完整组件源码恢复（E09）、云同步、小组与在线排名。

## 实施顺序

1. 核对 1.8.3 已交付行为与 BACKLOG 缺口，准备隔离数据、旧备份样本（含主题图片、计时会话、日程）和回退说明。
2. 完成壁纸请求边界（E14）与主题并发归属基础处理（E02），更新相关单元与浏览器用例。
3. 实现迷你计时窗口能力检测与回退（E11），先在 Chromium 验证，再确认 Firefox/Safari 回退。
4. 完成核心体验与能力降级核对，补充可取得的真实环境证据。
5. 冻结范围，跑全量回归与包体验收，整理升级说明，按维护指南合入 main、打 Tag、发布。

## 验收要求

- 运行生成一致性、单元、语法和完整浏览器检查；三系统 Node 22/24、ZIP/tar.gz 解压启动、文档链接均通过。
- 使用隔离数据验证：旧备份导入、跨标签、计时中断恢复、断网运行、主题切换。
- 壁纸：正常获取、失败、超时、跨日、已保存主题均符合预期。
- 迷你窗口：支持环境功能正确，不支持时明确回退且不另开 tick 或写库。
- 数据库、偏好、计时会话、通知已读、历史记录不因升级重置。
- 缺口和未完成验收只记 BACKLOG；完成后从 BACKLOG 移除，并在版本报告记录结果与证据。

## 约束

- 复用现有数据服务、计时适配器、共用控件和维护锁，不引入新数据库大版本。
- 界面与交互默认保持 1.8.x 视觉基准，仅明确需求的变化才验收差异。
- 任何持久化变更必须支持旧备份兼容，并写明回退限制。
- 发布仍走 `release.json` → `build:release` → CI → Tag `1.9.0` → Release → Pages。
