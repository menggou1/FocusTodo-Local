# 2.0.0 版本计划

[版本计划](README.md) · [统一待办与验收](../BACKLOG.md) · [维护指南](../MAINTENANCE.md)

目标：启用独立版本号，保持现有任务、计时、日程、报表、森林、成就和备份的数据与行为连续。本计划记录范围和验收标准，进度只在 BACKLOG 维护，不承诺固定发布日期。

## 范围与优先级

| 优先级 | 范围 | 完成标准 | BACKLOG |
|---|---|---|---|
| P1 | 独立版本号 | 从本版起应用版本和 Tag 均为 `2.0.0`；7.1.1 仅作为来源元信息。生成、显示、更新记录、打包、部署和发布门禁一致；旧版本记录和 Tag 保持原样 | E16 |
| P1 | 数据与升级兼容 | 1.x 备份可读取；升级不重置数据库、偏好、计时会话、通知已读和历史记录。说明兼容范围与回退限制 | E16、V07 |
| P2 | 壁纸请求边界 | 落实请求与重定向限制；验证跨域、超时、缓存过期、跨日刷新和断网回退，保持已保存主题可用 | E14、V05 |
| P2 | 核心体验与能力降级 | 核对任务、计时、日程、历史及报表；验证中英、亮暗、多宽度、键盘、减少动态效果与浏览器能力降级 | V02、V03、V04、V06 |

主题资源表、备份新容器、大包优化（E01–E04）暂不自动纳入本版。只有明确收益、兼容方案和验收资源后再调整范围；完整组件源码恢复（E09）继续单独管理。云账号、云备份、跨设备云同步、小组和在线排名不纳入范围。

## 实施顺序

1. 核对 1.8.1 已交付行为和实际缺口，在 BACKLOG 确定本版范围；先准备隔离数据、旧备份样本与回退说明。
2. 完成 E16：修改版本元信息与生成器，接通显示、历史识别、缓存、打包、部署及发布检查，再验证旧新版本和备份兼容。本次 1.8.1 仍使用 `7.1.1-local.1.8.1`。
3. 按 E14/V05 处理壁纸网络边界与失败回退；按已确定范围处理真实使用缺口，复用现有数据服务、计时适配器及共用控件。
4. 冻结范围，完成回归和包体验收，整理升级说明，再按维护指南合入 main、推送、部署与发布。

## 验收记录

- 运行生成一致性、单元、语法和完整浏览器检查；三系统 Node 22/24、ZIP/tar.gz 解压启动和文档链接均通过。
- 使用隔离数据核对旧备份导入、跨标签、计时中断恢复和断网运行。真实系统声音、通知及长期数据库仍须取得对应环境证据，不能由替身或模拟时钟代替。
- 检查同一提交的 main、Tag、Pages 和 Release；核对线上 `deployment.json`、项目子路径启动、应用显示和下载产物版本一致。
- 缺口和未完成验收仅记 BACKLOG；完成后从 BACKLOG 移除，并在最终版本报告记录结果、兼容范围和证据。
