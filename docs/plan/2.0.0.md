# FocusTodo-Local 2.0.0 独立应用重构计划

[版本计划](README.md) · [统一待办与验收](../BACKLOG.md) · [维护指南](../MAINTENANCE.md) · [English](../en/plan/2.0.0.md)

本文件是 2.0.0 的唯一详细实施路线图；稳定编号表示工作分解，不表示完成。状态、优先级和未完成验收只在 BACKLOG 维护，结果及证据写入版本报告。无发布日期承诺。审计依据为专用分支起点 `f102da8919e810006b6611aabcef5f0159057d61` 的代码与配置；下述待验证项不是已完成验收。涉及真实数据时使用授权的脱敏副本和隔离来源，禁止将私人备份、头像或数据库提交仓库。

## 目标、范围和约束

从压缩旧包、内部模块编号、运行时补丁和 AST 接入，迁移为可从受控完整源代码构建的独立 Web 应用；保持本地任务、计时、日程、报表、森林、成就、设置、备份、中英和现有交互视觉，保护已有数据。独立性涵盖运行、构建和测试依赖，而非只把旧包拆文件。云账号、云备份、跨设备云同步、小组及在线排名不纳入；其历史兼容数据仍须保留。E01 资源表、E03 新备份容器、E04 大包优化只有收益、兼容设计和验收资源明确后才纳入，不是独立化前提。E08 网络收口、E09 完整组件源码、E16 独立版本及 V02–V07 相关验收纳入本路线；原计划的壁纸边界与 V05 继续保留，旧计划 E14 已不在当前 BACKLOG，实际状态以代码和 BACKLOG 为准。

`main` 仍是稳定及唯一正式 Pages 来源，`dev` 保持日常开发；本路线实施在 `refactor/standalone-app`，最终发布前经完整验收再按届时维护规则处理。不能让实验入口访问真实来源数据。历史 Tag、Release 和记录不可改写；推送过的候选 Tag 不复用，失败修复递增第三位版本号。

## 当前架构审计与待查证据

### 入口与旧包

`src/index.html` 内联启动屏，异步加载 `main.css`、`local-controls.css`、`local-ui.css`，按 defer 顺序加载 i18n catalog/i18n、release、timer core、data、achievements、timer UI、app UI、backup、theme、settings、network、`patch.js`、calendar，最后 `js/main.js`。`patch.js` 安装本地身份、网络、备份 UI、设置兼容和主题；启动与数据恢复依赖 `FocusLocalReady`。旧包是已修改压缩代码，不是可从仓库完整重建的生成物。

旧包仍提供应用容器、侧栏/视图切换、任务及清单/子任务、报表历史、设置等核心组件和部分管理器；本地计时、日程、森林、资料与控件通过旧组件、事件、偏好、Redux store 和渲染入口协作。现有代码有 React/ReactDOM、Redux Provider/connect；导航以应用内部状态切换，完整 reducer、事件流及第三方版本尚未逐一证实，不能将架构文档中推测的组件树当成事实。AST 数组 1484 项包含库、运行时及应用代码，不等于 1484 个业务模块。阶段 A 要以调用证据建立功能归属与依赖清单，包括尚未发现的隐藏入口及实际可达性；不因旧包中存在功能就承诺恢复云服务。

`scripts/lib/bundle-editor.cjs` 用 Acorn 识别固定模块数组，检查唯一匹配、重叠及修改后语法；`revise-timer-integration` 接入计时实例、旧 React/ReactDOM 和迷你计时；`revise-app-integration` 处理启动、语言、订阅、森林及应用界面；`revise-controls-integration` 处理设置控件；`revise-pomodoro-rendering` 处理历史与番茄渲染；`revise-project-management` 处理清单管理；`revise-local-profile` 处理资料与身份；`revise-calendar-integration` 注入日程控制器、Redux 连接的旧选择器及数据写入。它们只修改既有包，不能还原源码。替代方式是明确服务和组件接口，逐功能转移并测试，最终由正常构建替代；一次性 `upgrade-*` 是历史工具，删除前判断证据保留需求。

### 本地代码的迁移分类

| 范围 | 实际依赖与处理 |
|---|---|
| `local-timer-core.js` | 纯状态转换优先保留并用 ESM 包装；迁移测试包含完整番茄、部分片段、暂停休息、时钟回退和恢复。 |
| `local-data.js`、`local-backup.js` | 复用业务校验、事务、日志、编码；先注入存储、时钟、通知和锁适配器，拆除对 `window`、旧事务包装及身份安装的隐式依赖。不能直接假定整文件可无改动复用。 |
| `local-theme-storage.js`、`local-i18n.js`、`local-network.js`、`local-release.js` | 保留有效策略、语言回退、数据和版本定义；分离 DOM、全局 API 包装、旧偏好和生成接口。网络按调用者重新收口，默认关闭外网及同源/精确 Bing 规则须有证据。 |
| `local-timer-ui.js`、`local-calendar.js` | 大量旧实例、React/Redux、DOM 和事件耦合；提取计时/日程领域规则，重建适配层和界面，保留生命周期、音频所有权、跨页刷新和写入语义。 |
| `local-achievements.js`、`local-app-ui.js`、`local-settings-ui.js` | 复用成就定义、提醒与设置规则；将接收旧 React 的 render、直接插 DOM、选择器和旧设置安装改为受控组件/服务。森林数据与奖励事务保持一致。 |
| `local-startup.js`、样式及资源 | 保留实际加载/恢复就绪语义、首屏和既有 token/资源；审计选择器、字体、焦点、暗色及布局后逐视图迁移，不保留对旧 DOM 的无主覆盖。 |

### 持久化与兼容合同

`PomodoroDB6` 版本 **3** 包含 `Project`、`Task`、`Subtask`、`Pomodoro`、`Schedule`、`Group`、`GroupUser`、`Message`、`TimerSession`、`LocalMeta`；前八项为历史业务数据，后两项保存会话及维护/恢复元信息。另有 `PomodoroDB6-maintenance-lock` v1 的 `ownership` 锁库。`local-data.js` 使用同事务记录及会话游标、维护标记、设置恢复日志，Web Locks（可用时）、队列、锁库和 BroadcastChannel 协调；旧管理器写入还依赖被包装的数据库 transaction。主题另有 `FocusTodo.themeJournal`，须在导入日志恢复后恢复。禁用能力时实际回退及竞争安全性须通过测试证实，不推断无锁即安全。

localStorage 不只是几项设置：包括 `Version='6.5'`、`ExpiredDate`、`cookie.*` 本地身份、计时长度与声音、`timingTaskId`/`timingSubtaskId`、`FocusTodo.language`、`FocusTodo.releaseRead`、`FocusTodo.taskRemindersRead`、`FocusTodo.forestState`、主题及 data URL、网络和历史偏好。备份快照包含大多数键，内部主题日志除外；阶段 A 须从旧包和本地代码建立键、默认值、读写者和保留规则清单，不以本表为穷举。完整 JSON/Gzip 备份支持 exportVersion 1/2，当前导出 2；按内容识别、限制 128,000,000 字节并校验数据、图片引用和较新 DB 版本。无压缩 API 时按现有能力降级。导入涉及 IndexedDB 和 localStorage，必须保留失败回滚及中断恢复语义。

产品 `2.0.0`、数据库 schema v3、备份 exportVersion 和旧 `Version='6.5'` 是不同标识；版本更名不触发删库、重置或无依据升库。保留任务/子任务关联、计时片段与活动会话、日程、历史、森林、头像及原图、语言、已读和未知兼容字段。来源由协议、主机和端口决定：同来源不同路径共用数据，Pages 与 loopback 不共用。新旧版本不能仅靠新代码声称互斥：旧客户端可能不遵守新协议。默认禁止在同来源同时运行新旧写入者；实施前验证旧标签关闭、阻塞/过期检测与用户提示，对无法证明的旧客户端采取隔离来源或只读导入；跨版本写入和回退必须有实测兼容矩阵及明确禁止条件。升级前导出并确认可读备份；不保证降级能读取新格式，必要时仅允许恢复升级前备份，清楚说明升级后新增数据不会自动合并。

### 工程、发布与许可证

现为 Node 22+ 静态应用，`scripts/runtime-layout.json` 是服务、Pages 和包共享白名单；Node/Python loopback 服务及 Windows/macOS/Linux 启动器不依赖安装运行时以外的 npm 包。`deploy-pages.py` 从指定提交映射目录并写 `deployment.json`；`package-release.py` 输出 ZIP/tar.gz，解压启动由 smoke 测试验证。`release.json` 是人工发布元信息，`build-release.cjs` 同步版本、页面、缓存、i18n 回退等；历史报告保留。CI 预检、三系统 × Node 22/24，Node 24 三系统 Chromium 和包验收，Linux 兼容测试；Tag 全矩阵成功后发布，Pages 仅 main。现有 unit、browser、fixtures、startup/backup performance、release gate 和 Pages tests 是基线，不代表所有真实 Safari、通知和长期数据已验证。

根 `LICENSE` 为 MIT，`package.json` 声明 ISC，两者需核实并纠正实际授权/声明差异；Noto 字体附 OFL，其他字体、图片、音频及旧 bundle 内第三方组件未见逐项许可清单，不能推断均可再分发。阶段 A 建立来源、版本、许可证、版权/通知和分发证据清单，审计旧包许可证注释与依赖来源；缺证素材先取得授权或替换并复测视觉/音频，再发布。新依赖由包管理器锁定并审查许可证、浏览器支持、维护、安全及体积；不能仅凭压缩代码推断精确版本或授权。

## 目标架构与决策

首选 React + TypeScript + Vite，作为阶段 B 的有条件决策：以锁定版本的最小原型验证项目子路径、静态便携包、受支持浏览器、离线冷启动、调试和现有样式；不满足则记录证据并选择能满足合同的替代。React 组件采用应用壳/导航、任务、计时、日程、报表、森林/成就、设置/备份和共享弹窗的领域边界。导航先用显式状态及 URL 需求评估，不预设路由库。数据以服务为事实来源；界面状态由 React context/reducer 或小型外部 store 管理，事务和计时不放在组件生命周期中；是否需要 Redux 由事件顺序和复杂度原型决定，禁止依赖旧 store 内部结构。

建议 `app/` 入口与启动、`domain/` 纯业务、`services/` 数据/备份/时钟/网络/通知、`features/` 组件与状态、`shared/` 控件/i18n、`styles/` 和 `assets/`；具体目录由 B 原型确定。领域函数显式输入输出，服务暴露异步命令、快照与订阅及错误类型；组件通过注入接口调用，不直接操作 IndexedDB 或猴补浏览器全局。保留验证充分的 JS，以 ESM 边界和 JSDoc/类型声明先接入，逐步迁 TypeScript；禁止为追求全 TS 改写稳定算法。旧桥只用于迁移，标注所有者和删除门槛。

启动顺序：首屏与必需样式 → 本地能力和版本检查 → 独占/兼容检查 → DB 打开及导入日志恢复 → 主题日志恢复 → 计时恢复及服务初始化 → 组件挂载；可选字体、图片和页面异步加载不得阻塞可用性。失败显示可操作提示及备份/重试路径，禁止静默重置；离线运行依赖本地发布资源，不假定已有 service worker。若引入缓存，必须设计升级、失效、回滚及旧缓存冲突并测试；无缓存时说明首次获取资源的限制。i18n 迁移原词库、`local-en.json`、回退与用户语言键，覆盖中英且不翻译用户内容。保留现有样式和资源，通过基线逐步拆分；不以像素差为唯一视觉结论。

Vite 产物应由共享运行清单明确映射至 Pages 和便携包，使用相对 base 验证项目子路径和 loopback；运行时不依赖 CDN 或 npm。保留生成元数据单一来源，确保本地服务和包一致；以真实解压产物测启动与资源，而非只测开发服务器。版本机制在骨架阶段先设计、以测试数据验证，切换实际 `2.0.0` 在功能完成及发布准备时实施；与架构切换可分提交，但不得因版本命名迁移数据。7.1.1 仅来源元信息，旧版本识别、更新历史、已读、缓存、包和 Tag 检查按 E16 迁移。

## 分阶段实施

每阶段的编号是稳定任务标识；均为必须项，标注“可选”的除外。允许在各阶段中分批提交；通过该阶段退出条件后才进入依赖阶段。A 先于骨架以建立可对比证据；C 和 D 可在 B 后按接口合同交错，但每个 D 功能依赖其 C 服务；E 必须先完成所有功能及对应回归，F 完成最终验收。E 的切换先在隔离候选产物验证，正式入口与删除分开提交，以便安全回退。

### A：架构审计与行为基准

- **目标/前置**：建立可复现基准和全功能归属；前置为固定旧提交、隔离环境和不含私人数据的样本。
- **范围**：`src/index.html`、旧包、全部 local 模块及样式、AST 脚本、资源、`tests/`、工作流和旧备份。
- **任务**：**A01** 逐页面/操作列出功能、触发、数据、负责代码及旧/新依赖，含键盘、错误、空态和排除范围；**A02** 追踪旧 React/Redux、事件和导航、计时生命周期、脚本具体接入与第三方身份，标记推断；**A03** 建 DB/store/index、设置键、格式及多标签协议清单，构造 v1/v2 备份、v3 真实脱敏长期副本和损坏/中断样本；**A04** 在固定提交、浏览器、系统、语言、主题、视口、缩放和数据下采样截图、computed style、交互轨迹、冷暖启动、内存与产物大小，保存方法和环境；**A05** 将现有测试与功能矩阵交叉标注盲区、补充方案；**A06** 完成资源/依赖授权清单和替代方案。
- **决策**：证据来自代码及隔离运行，第三方组件不按 bundle 模块数估工；真实数据不得进 CI。
- **验收/退出**：每个必要功能有责任归属、基准、测试及缺口；数据格式、许可证不明项有负责人、验证方法和阻断条件；记录基线提交及可重现环境。
- **风险/回退**：压缩代码归属不明先做黑盒追踪，不能把猜测作为完成；仅用隔离副本。**交付**：审计矩阵、样本生成器/私有样本使用说明、基准及差距记录。

### B：独立工程骨架

- **目标/前置**：建立可构建、可观察的独立入口；依赖 A 基线及隔离合同。
- **范围**：新入口、依赖锁、目录、资源、构建/服务及测试脚手架。
- **任务**：**B01** 验证 React/TS/Vite 及浏览器、许可证、包体，决定版本和状态方案；**B02** 建立模块与依赖方向、注入式服务接口、类型检查和调试 sourcemap 策略；**B03** 实现启动屏、错误边界、i18n/样式骨架和可选异步加载；**B04** 设计独立测试 origin/临时端口与合成数据，新旧对照不共享生产存储，保留旧入口处理所有未迁移功能；**B05** 原型验证相对路径、Pages 子路径和两个解压包的离线资源加载。
- **决策**：候选入口只供隔离验收，不在正式页面混合双应用写入；引入依赖需锁定与许可证审计。
- **验收/退出**：干净安装可构建，候选启动、失败提示、语言和资源路径可复现；旧应用功能未被提前替换；接口及原型证据通过审查。
- **风险/回退**：构建工具或字体不兼容时保留旧入口，替代方案先通过同等原型。**交付**：骨架、接口合同、构建和验证说明。

### C：核心服务迁移

- **目标/前置**：保持持久化与业务语义的独立服务；依赖 A 样本、B 接口。
- **范围**：data、timer、backup、calendar、theme、i18n、network、release 和跨标签服务。
- **任务**：**C01** 将数据库访问、索引、事务、并发、锁及异常恢复置于显式服务，故障注入验证每个提交边界；**C02** 迁计时核心/会话、片段、任务归属、音频协调和中断恢复；**C03** 迁清单、任务、子任务、日程、提醒及历史/报表聚合；**C04** 迁 JSON/Gzip 导入导出、大小校验、完整回滚及主题日志；**C05** 迁主题图片、身份、设置、语言和通知；**C06** 收口网络策略，验证重定向、超时、跨日、取消、缓存与离线；**C07** 设计旧新版本识别、生成和已读兼容；**C08** 实测多标签互斥、旧客户端、版本变更/blocked、崩溃和降级；**C09** 对每个接口运行旧新同输入差分及错误路径测试。
- **决策**：默认保留 DB v3 和格式；确需 schema 变更须先做可恢复迁移、版本协商及回退评审，不以删除数据库解决。
- **验收/退出**：各服务满足旧样本、同事务与故障恢复合同；已覆盖旧新并发安全边界，不能证明安全的组合明确阻止；供 D 的接口冻结且测试通过。
- **风险/回退**：跨 IndexedDB/localStorage 非单一事务，保留日志及故障注入；失败使用升级前备份恢复隔离副本，不能覆盖有新写入的数据。**交付**：服务、差分和事务测试、兼容矩阵。

### D：独立 UI 重建

- **目标/前置**：逐视图替代旧组件，依赖 B 和对应 C 服务。
- **范围**：React 组件、共享控件、资源、i18n 与样式。
- **任务**：**D01** 应用布局、侧栏和导航；**D02** 清单、任务、子任务、搜索和拖动；**D03** 计时器、迷你窗口、音频与控件；**D04** 日程/提醒；**D05** 历史、报表及跨日/时区；**D06** 森林、成就与收取；**D07** 设置、主题、资料和备份恢复；**D08** 通知、更新、弹窗、焦点和错误；**D09** 每批对照 A 的交互/截图/computed style，覆盖中英、亮暗、视口、键盘及减少动态效果，补齐旧功能矩阵。
- **决策**：组件仅调用服务，避免依赖旧 Redux、DOM、模块编号；样式按已验证视觉逐步接管。可选优化需另行决定，不改变验收基线。
- **验收/退出**：每项 D01–D08 均通过对应功能、数据、视觉和错误回归；已知差异经明确批准并有证据；全功能矩阵无未映射必要行为。
- **风险/回退**：先在候选入口替换单领域并保留旧入口；不共享真实数据，发现回归撤销该领域切换。**交付**：组件、可访问性/视觉/交互测试和对照证据。

### E：退出旧架构

- **目标/前置**：从候选正式切换并清理旧依赖；C、D 所有必要功能及回归通过。
- **范围**：正式入口、旧包、patch、AST 工具、桥接、样式、运行文件清单、测试和架构文档。
- **任务**：**E01** 在隔离构建先切换入口并核对全部场景，正式切换单独提交；**E02** 扫描运行、构建、测试及包内文件对 `main.js`、`patch.js`、旧模块编号、旧 React/Redux 实例、全局变量、旧 DOM 选择器和 AST 工具的依赖，结合动态覆盖/网络请求检查；**E03** 逐项移除无调用代码、旧资源和工具并验证，再清除构建清单；**E04** 区分历史报告/证据与可删除工具，保留归档和许可证记录；**E05** 更新架构、开发、调试和打包文档。
- **决策**：先验证后删除，历史证据及原版权声明保留；搜索无结果不能单独证明无动态依赖。
- **验收/退出**：干净 checkout 可独立构建运行、测试和打包；依赖清单无旧运行/构建/测试耦合，全部功能及兼容测试通过。
- **风险/回退**：入口切换和删除分提交，回退代码前核对数据格式及活跃标签；必要时从升级前备份恢复，不承诺合并新旧写入。**交付**：清理后的源码、依赖退出证据、更新文档。

### F：完整验收与发布准备

- **目标/前置**：建立可发布证据；依赖 E 全部退出条件。
- **范围**：真实浏览器、数据、产物、版本、CI、Pages 与便携启动。
- **任务**：**F01** 全量 unit、语法/类型、浏览器及缺口测试，三系统 × Node 22/24，三系统 Chromium、Firefox/WebKit 和真实 Safari 的适用范围；**F02** 用隔离真实长期副本及历史备份测试原地升级、导入、导出、暂停休息、跨标签、崩溃、时钟回退、主题和回退限制；**F03** 真实系统声音/通知、离线、网络控制、语言、主题、视口和可访问性；**F04** 相同环境多次测冷暖启动、峰值内存和资源大小，对照 A 中位数及分布；默认不得劣化超过 10%，超出须分析噪声、复测并经明确批准，缺少可比样本不得宣称通过；视觉以固定截图、尺寸、裁剪、交互和 computed style 对照，差异逐项审核，无未经批准的明显回归；**F05** 验证项目子路径 Pages 构建、ZIP/tar.gz 解压启动与离线资源、版本元数据、校验和及发布门禁；**F06** 实施 E16 生成/显示/旧新版本识别、已读、缓存、更新记录与 Tag 检查，保留历史，演练失败候选递增规则；**F07** 汇总授权、已知限制、升级和回退说明，验证同一提交各产物；正式发布、main Pages 和真实 Tag 按届时单独授权与维护指南执行。
- **决策**：模拟时钟、替身通知和 WebKit 不代替真实系统/Safari；性能门槛须在 A 基准中记录硬件、样本数和测试方法。
- **验收/退出**：F01–F07 均有可复核证据；未完成实际环境验收留 BACKLOG，阻断正式发布的事项不得标记通过；发布时核对 main、Tag、线上 `deployment.json` 及附件来源一致。
- **风险/回退**：不发布未获授权素材；失败保留诊断与旧入口/备份，候选 Tag 已推送时使用新修复版本。**交付**：验收报告、兼容矩阵、升级回退指南及待发布产物。
